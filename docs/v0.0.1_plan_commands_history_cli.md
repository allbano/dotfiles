# Plano de Implementação: Deduplicação e Organização do Histórico em Go (DDD)

Este plano descreve a implementação de um utilitário em **Go** chamado `cmdsh` estruturado sob a arquitetura **Domain-Driven Design (DDD)** para consolidar e ordenar o histórico de comandos.

---

## Objetivo

Criar um executável nativo em Go chamado `cmdsh` que:
1. Leia o arquivo `/home/$USER/.bash_history`.
2. Leia o arquivo `/home/$USER/github/dotfiles/bash/history/commands_history`.
3. Deduplique os comandos usando a camada de domínio com um mapa.
4. Ordene os comandos alfabeticamente.
5. Escreva o resultado de volta para o arquivo `commands_history` caso novos comandos tenham sido detectados.
6. Permita compilação executando apenas `go build .` dentro do diretório `/home/$USER/github/dotfiles/cmdsh/`.

---

## Arquitetura DDD Proposta

O projeto foi dividido em camadas lógicas para isolar a regra de negócio da infraestrutura de arquivos:

```
cmdsh/
├── go.mod
├── main.go                       # Camada de Apresentação (Ponto de entrada)
└── internal/
    ├── domain/                   # Camada de Domínio (Entidades, Agregados, Repositórios)
    │   ├── command.go            # Entidade: Command
    │   ├── history.go            # Agregado: History
    │   └── repository.go         # Interface: HistoryRepository
    ├── application/              # Camada de Aplicação (Casos de Uso)
    │   └── sync_history.go       # Caso de Uso: SyncHistoryUseCase
    └── infrastructure/           # Camada de Infraestrutura (Acesso a Arquivos)
        └── file_repository.go    # Implementação de HistoryRepository no disco local
```

---

## Detalhes dos Componentes e Código

### 1. Camada de Domínio (`cmdsh/internal/domain`)

- **`command.go`**: Representa a entidade `Command`. Filtra espaços em branco, linhas vazias e comentários/timestamps do bash (linhas começadas com `#`).
- **`history.go`**: O agregado `History` gerencia uma coleção única de comandos, realizando a fusão (`Merge`) de novas entradas e ordenando-as alfabeticamente.
- **`repository.go`**: Define a interface `HistoryRepository` para isolar como o histórico é carregado e salvo.

### 2. Camada de Aplicação (`cmdsh/internal/application`)

- **`sync_history.go`**: Contém o caso de uso `SyncHistoryUseCase` que orquestra a lógica de buscar os históricos através do repositório, efetuar o merge e salvá-los no destino final se houver comandos novos.

### 3. Camada de Infraestrutura (`cmdsh/internal/infrastructure`)

- **`file_repository.go`**: Implementa a interface do repositório usando o sistema de arquivos local (`os`, `bufio`, `path/filepath`), lidando com arquivos inexistentes de forma segura.

### 4. Camada de Apresentação (`cmdsh/main.go`)

- **`main.go`**: Responsável por obter o usuário atual via variáveis de ambiente, definir os caminhos dos arquivos, instanciar a infraestrutura e executar o caso de uso.

## Como Compilar e Executar

Para compilar o utilitário nativo de forma organizada, entre na pasta do projeto e execute o compilador do Go:

```bash
cd /home/$USER/github/dotfiles/cmdsh
go build .
```

Isso gerará o executável nativo `cmdsh` diretamente no mesmo diretório.

Para executá-lo manualmente:
```bash
/home/$USER/github/dotfiles/cmdsh/cmdsh
```

## Plano de Verificação

### Testes Manuais

1. **Compilação**:
   Executar `go build .` na pasta `cmdsh` e certificar-se de que o executável `cmdsh` é criado com sucesso.
2. **Funcionalidade**:
   - Rodar o utilitário `/home/$USER/github/dotfiles/cmdsh/cmdsh`.
   - Verificar se o arquivo `/home/$USER/github/dotfiles/bash/history/commands_history` foi gerado/atualizado.
   - Confirmar que não há entradas duplicadas e que todas estão em ordem alfabética.
3. **Performance**:
   - Rodar temporizado usando o comando `time`:
     ```bash
     time /home/$USER/github/dotfiles/cmdsh/cmdsh
     ```
