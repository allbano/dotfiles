# Plano v0.2 — helper interativo para alteração de fonte

## Objetivo

Implementar um helper comum, acionado pelo tmux, para selecionar
interativamente a família e o tamanho da fonte do terminal externo ativo.

O helper deverá manter um perfil central e aplicar a alteração por meio da
interface nativa de cada terminal suportado:

- Ghostty;
- Alacritty;
- Kitty.

O tmux será somente o ponto de entrada e o responsável por identificar o
cliente que disparou a operação. A fonte continuará pertencendo ao emulador
gráfico externo.

## Escopo da versão 0.2

- Adicionar um helper Bash reutilizável, proposto como
  `scripts/change-terminal-font`.
- Abrir um seletor interativo com `fzf` dentro de um popup do tmux.
- Selecionar família e tamanho da fonte.
- Persistir a seleção em um perfil central fora dos arquivos específicos dos
  terminais.
- Aplicar a alteração imediatamente à janela externa associada ao cliente
  tmux atual.
- Fazer com que novas janelas carreguem o perfil selecionado.
- Detectar o terminal usando os dados do cliente tmux e o ambiente do processo
  externo, sem alterar o valor de `TERM`.
- Exibir uma mensagem curta no tmux informando o resultado ou o erro.
- Preservar integralmente a barra de status, os temas, a opacidade e os demais
  bindings já existentes.

## Fora de escopo

- Alterar a barra de status ou a aparência dos painéis do tmux.
- Criar um protocolo universal baseado apenas em OSC 50.
- Modificar o `TERM` para tentar identificar o emulador.
- Aplicar a alteração a processos gráficos de outra máquina durante uma sessão
  SSH.
- Reescrever todo o arquivo de configuração a cada troca interativa.
- Sincronizar alterações manuais feitas diretamente na interface gráfica com o
  perfil central.
- Implementar adaptadores para terminais que não estejam listados no escopo.

### Falhas encontradas na validação real

1. O Alacritty recebia `ALACRITTY_SOCKET` apenas como variável de ambiente,
   embora a versão instalada exija o argumento global `--socket`. A operação
   falhava e o rollback restaurava o perfil, dando a impressão de que a fonte
   nunca havia sido salva.
2. O modo interativo guardava a saída do `fzf` em `SELECTED_FAMILY` e
   `SELECTED_SIZE`, mas `apply_selected_profile` recarregava logo em seguida os
   valores antigos de `PROFILE_FAMILY` e `PROFILE_SIZE`. A escolha era exibida,
   porém nunca chegava aos adaptadores.
3. Kitty e Alacritty alteravam a opacidade somente no processo corrente. Ao
   reiniciar, ambos liam novamente o valor base `0.8` de suas configurações.
4. O catálogo usava a expressão Fontconfig na posição errada e a validação
   aceitava somente o primeiro nome de cada família. Nomes alternativos
   legítimos, como `CaskaydiaCove NF`, apareciam no `fzf`, mas eram rejeitados
   ao aplicar.
5. O `fzf` podia herdar `--select-1` ou `--exit-0` do ambiente. O helper agora
   força `--no-select-1 --no-exit-0` e usa toda a área do popup do tmux.
6. O arquivo do Kitty continha duas opções não reconhecidas pela versão 0.48;
   elas foram comentadas para que o reload não produza configuração parcial ou
   avisos que ocultem o erro real.

## Arquitetura proposta

Fluxo principal:

```text
<C-Space> F
    -> tmux abre display-popup
    -> fzf seleciona perfil/família/tamanho
    -> helper grava o perfil central
    -> helper identifica o cliente tmux atual
       -> Ghostty: override gerenciado + reload
       -> Alacritty: IPC `alacritty msg config`
       -> Kitty: controle remoto + reload de configuração
    -> tmux mostra o resultado
```

O binding deverá ser adicionado em
[tmux/.tmux.conf](/home/albano/github/dotfiles/tmux/.tmux.conf:23),
preferencialmente como `<C-Space> F`, depois de confirmar que a tecla está
livre.

## Perfil central

Criar uma área de configuração própria, por exemplo:

```text
~/.config/dotfiles/terminal-fonts/
├── current.conf
└── profiles/
    ├── default.conf
    ├── compact.conf
    └── presentation.conf
```

O formato deve ser simples e não depender de `eval`, por exemplo:

```text
family=RecMonoCasual Nerd Font
size=12
style=Regular
```

Requisitos do perfil:

- validar a família com `fc-match` antes de gravar;
- listar somente fontes monoespaçadas instaladas;
- guardar tamanho como número positivo dentro de uma faixa razoável;
- permitir que os adaptadores traduzam `style` para a sintaxe própria de cada
  terminal;
- gravar atomicamente e proteger alterações concorrentes com `flock`;
- não sobrescrever configurações do usuário sem backup ou confirmação.

A família padrão deverá ser escolhida após uma comparação visual entre as duas
famílias já instaladas, pois as configurações atuais não usam a mesma fonte.

## Interface prevista do helper

```text
change-terminal-font
change-terminal-font profile <nome>
change-terminal-font family <nome>
change-terminal-font size <pontos>
change-terminal-font status
change-terminal-font reset
```

Comportamento padrão:

- sem argumentos: abrir o seletor interativo;
- `profile`: carregar e aplicar um perfil conhecido;
- `family`: preservar o tamanho atual e trocar somente a família;
- `size`: preservar a família atual e trocar somente o tamanho;
- `status`: mostrar o perfil central e o terminal detectado;
- `reset`: restaurar o perfil padrão.

O modo interativo deverá usar `tmux display-popup -E` com `fzf`. Se o popup não
estiver disponível, deverá existir fallback para executar o seletor no painel
atual.

## Adaptador do Ghostty

- Reutilizar o mecanismo de `config-file` já usado para o estado de
  transparência.
- Não adicionar um segundo arquivo override sem validar como o Ghostty combina
  múltiplos `config-file`.
- Preferencialmente consolidar transparência e fonte em um único arquivo de
  estado gerenciado, preservando os valores existentes.
- Ao escrever uma nova família, emitir primeiro `font-family = ""` para limpar
  valores repetidos anteriores e depois escrever a família selecionada.
- Escrever `font-size` no mesmo override.
- Recarregar por `systemctl --user reload app-com.mitchellh.ghostty.service` ou
  pelo mecanismo já validado no helper de transparência.
- Confirmar se uma alteração manual anterior do tamanho impede a atualização
  automática e, nesse caso, informar o resultado ao usuário.
- Não alterar tema, shell, bindings, opacidade ou comandos de inicialização.

Referências de implementação: [configuração do Ghostty](https://ghostty.org/docs/config/reference)
e [reload via systemd](https://ghostty.org/docs/linux/systemd).

## Adaptador do Alacritty

- Usar o socket identificado pelo ambiente do cliente tmux.
- Aplicar a alteração imediata com `alacritty msg config` apenas à janela
  correspondente ao cliente atual.
- Atualizar `font.size` e as entradas `font.normal`, `font.bold` e
  `font.italic` conforme o perfil.
- Usar `get-config` para validar a resposta quando necessário.
- Não usar `-1` por padrão, pois isso alteraria todas as janelas Alacritty do
  usuário.
- Reorganizar a configuração persistente para que o fragmento gerado pelo
  perfil tenha precedência sobre o bloco de fonte atual.
- Tratar socket ausente, janela obsoleta e resposta inválida sem interromper o
  servidor tmux.

Referências de implementação: [configuração do Alacritty](https://alacritty.org/config-alacritty.html)
e [comando `alacritty msg`](https://alacritty.org/cmd-alacritty-msg.html).

## Adaptador do Kitty

- Reutilizar `KITTY_LISTEN_ON` e a resolução de socket já existente.
- Aplicar tamanho imediatamente com `kitten @ set-font-size`.
- Aplicar família por meio de um fragmento gerado e `kitten @ load-config`.
- Preservar `font_family`, `bold_font`, `italic_font` e
  `bold_italic_font` de forma consistente.
- Garantir que o comando atinja somente a janela associada ao cliente atual;
  não usar `--all` no primeiro incremento.
- Validar a segurança de `allow_remote_control socket-only` e restringir o
  socket ao usuário local.
- Tratar socket ausente, socket obsoleto e controle remoto indisponível sem
  bloquear o tmux.

Referências de implementação: [controle remoto do Kitty](https://sw.kovidgoyal.net/kitty/remote-control/)
e [protocolo de controle remoto](https://sw.kovidgoyal.net/kitty/rc_protocol/).

## Persistência e arquivos gerados

O perfil central será a fonte de verdade. Cada adaptador deverá gerar somente o
fragmento necessário para o seu terminal:

- Ghostty: override de fonte integrado ao override de runtime existente;
- Alacritty: fragmento TOML carregado depois da configuração base;
- Kitty: fragmento de configuração incluído pelo `kitty.conf`.

Os fragmentos deverão:

- ser escritos com arquivo temporário no mesmo diretório e `mv` atômico;
- manter permissões restritas ao usuário quando contiverem estado local;
- não conter comandos shell derivados diretamente da entrada do usuário;
- permitir rollback para o perfil anterior.

## Detecção do cliente

O helper deverá receber do tmux:

```text
#{client_termname}
#{client_name}
#{client_pid}
```

Ordem de detecção:

1. normalizar `client_termname`;
2. validar o PID e confirmar que pertence ao usuário atual;
3. ler, quando disponível, o ambiente do processo externo em `/proc/<pid>`;
4. procurar as variáveis e sockets específicos do terminal;
5. recusar a operação se houver ambiguidade.

O helper não deverá inferir o terminal pelo valor interno de `TERM`, pois o
tmux deve continuar usando `tmux-256color`.

## Segurança e tratamento de falhas

- Não usar `pkill`, sinais para árvores de processos ou globais amplos.
- Validar sempre PID, UID, socket e caminho de configuração.
- Não executar o nome da fonte como código shell.
- Usar lista gerada pelo Fontconfig ou validação explícita antes de gravar.
- Mostrar no tmux uma mensagem curta e útil.
- Enviar detalhes técnicos para stderr e para um modo de diagnóstico opcional.
- Não habilitar passthrough global do tmux apenas para fazer a troca de fonte.

## Critérios de conclusão

- `<C-Space> F` abre o seletor nos três terminais suportados.

- Novas janelas carregam o perfil persistido.
- Os três adaptadores usam suas interfaces nativas sempre que disponíveis.
- Falhas de IPC ou sockets não encerram o servidor tmux.

- O perfil pode ser restaurado com `change-terminal-font reset`.
